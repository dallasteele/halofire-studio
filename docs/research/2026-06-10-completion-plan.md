## 1. Executive Summary

**Health grade: C.** The foundations are genuinely good — a pure, tested, single-chokepoint undo history; deterministic dependency-injected libs for routing/hydraulics/takeoff/bid; real-pricebook pricing; and an honesty contract that is enforced in code, not just prose. But the product cannot currently complete its one mission: an operator cannot take the real PDF-only 1881 set from import to bid, because work evaporates on refresh (no save/open), plan sheets cannot be traced (no pan/zoom — sub-pixel precision at fit-to-screen), and the predecessor pipeline's 1881 geometry (1758 pipes / 1303 heads in `design.dxf`) has no bridge into `project.network`. **Top 3 risks:** (1) hydraulics omits the density/area flow floor, so the supply-adequacy verdict can be optimistic in the unsafe direction and a bid can under-price upsizing; (2) the green "1881 acceptance test" proves file readability, not the plan→bid chain, giving false confidence; (3) `routeSystem` wholesale-replaces the network, destroying every manual diameter override, so the operator can never converge on an installable layout. **Top 3 opportunities:** (1) the `mutate` chokepoint means save/open, selection, and manual pipe all inherit undo for free; (2) the 1881 kernel DXF uses clean `HALOFIRE_HEADS`/`HALOFIRE_PIPES` layers (verified on disk), making a deterministic network importer a contained pure module; (3) the agent loop is a proven harness currently aimed at Phase-4/6 leaves — re-pointing its backlog at pure substrate modules (viewport math, project I/O, selection sets, density floor) lets the local model build the bricks while Claude does only the wiring.

## 2. Themes

### Theme A — "The operator's work must survive and be doable" (persistence + navigation)
The two Critical operator-killers (no save/open, no pan/zoom) share a root cause: the app was built outside-in from the math libs, and the operator-session shell never landed. **Target state:** a `.hfcad` JSON project file with Save/Open in the File tab, localStorage autosave as a crash net, and a wheel-zoom/drag-pan viewport with a live zoom readout, accurate enough to click two door jambs on a 30×40 sheet. **NOT fixing:** cloud sync, multi-user, conflict resolution, project browser UI — single-file, single-operator is the maturity bar. Trade-off: an operator can still lose work between autosaves if they never hit Save; acceptable for an internal tool.

### Theme B — "Reach the real 1881 job" (extraction lane + multi-sheet + multi-level)
The rebuild cannot reach the building its predecessor already modeled. **Target state:** a kernel-DXF import lane that turns `design.dxf` into real `project.network` HEAD nodes and pipe segments (not inert wall candidates), a PDF page picker so sheets other than page 1 load, and minimal per-level tagging so a multi-story building is representable. **NOT fixing:** automatic wall/room vectorization from raster PDFs (true CV extraction), automatic hazard classification, per-floor riser hydraulic stacking beyond elevation head — the operator still traces/classifies what the kernel doesn't carry. Trade-off: 1881 remains partly manual; the goal is *days→hours*, not zero clicks.

### Theme C — "The operator must be able to disagree with the machine" (edit verbs)
Auto-route is accept-or-reject-wholesale: no manual pipe, destructive re-route, single-pick selection. **Target state:** a click-to-draw Pipe tool, re-route that preserves manually-flagged segments and diameter overrides, and a marquee/multi-select with bulk delete. **NOT fixing:** Copy/Rotate/Mirror/Array, constraint solving, automatic clash detection against beams/shafts — the operator routes around obstructions by hand. Trade-off: large cleanups stay tedious, but they become *possible*.

### Theme D — "Green must mean something" (truthful gates + truthful docs)
The acceptance test stops at parsing; the parity plan misreports its two biggest wins (Undo/Redo, T29-T34) as missing; two ribbon buttons silently no-op; the understated density demand hides behind a disclaimer. **Target state:** a chained 1881 acceptance test (kernel import → hydraulics → takeoff → priced bid asserted against real ground truth: 1303 kernel heads, $538,792.35 actual proposal as a sanity *band*, not an equality), a density-floor in head demand, the parity-plan status column re-verified, and every visible button either working or removed. **NOT fixing:** matching the $538k number (different scope/years/labor — assert order-of-magnitude band only), full NFPA-13 calc-report parity, golden-file plotting tests. Trade-off: the acceptance band is loose; tightening it is future calibration work, honestly labeled.

### Theme E — "Point the free capacity at the load-bearing wall" (agent-loop retargeting)
The loop spends autonomous capacity on Phase-4/6 polish while Phase-0/1 blockers wait, and finished modules (hydrant-flow) idle unwired. **Target state:** Wave 2 backlog (Section 4) of pure substrate modules that directly de-risk the Critical/High items, plus a standing Claude integration queue (Section 5) so nothing lands and idles. **NOT fixing:** letting the loop touch UI/store — its purity constraint is the reason its gates are trustworthy; keep it.
